# 促销模板 批量导入功能 PRD 文档

> 模块：促销中心 / 促销模版 / 促销模板
> 功能：促销模板批量导入（Excel）
> 文档版本：V1.0 ｜ 对应原型版本：2026-07-04
> 说明：本文档只描述逻辑（流程、校验、写入、状态、异常），不含界面元素清单与接口字段细节。

---

## 1. 整体说明

### 1.1 功能定位

促销模板批量导入，用于业务人员通过 Excel 一次性创建多个促销模板，替代逐个新建向导的重复操作，适用于：

- 新业务上线时批量铺模板（如集团统一一类活动，需在各区域分别建模板）。
- 从历史系统/外系统迁移已存在的模板配置。
- 测试/演示环境快速造数。

### 1.2 业务边界

| 范围内 | 范围外 |
|--------|--------|
| 模板**基本属性 + 能力开关**的批量导入 | 模板内**明细列表**的导入（阶梯档位明细、商品范围明细、时段明细等结构化列表） |
| 导入后的模板默认进入**草稿**态（可选提交审核） | 模板的算价、出券等运行期逻辑 |
| 导入模板的校验、错误反馈、错误报告下载 | 模板被活动引用后的引用数维护 |
| 基于导入数据生成符合类型的 config 嵌套结构 | 修改/覆盖**已存在**模板（本期只做"新增"型导入） |

> 关键取舍：促销模板是多层嵌套结构（basic / object / conditions / rewards），明细列表（如阶梯档位数组、商品范围数组）无法稳定地用二维表表达，**本期导入只覆盖"模板主信息 + 各能力开关的勾选状态"**，明细列表仍需导入后在向导中补配。

### 1.3 核心概念

- **导入任务（Import Task）**：一次上传对应一个导入任务，记录文件、总行数、成功/失败数、状态、操作人、时间，供结果追溯。
- **能力开关导入**：Excel 中每一列对应模板向导里的一个能力开关（布尔值），导入即"批量勾选能力开关"。
- **类型能力矩阵**：模板类型（直降/折扣/满减满赠/满赠券）决定哪些能力开关可见可勾，是导入校验的核心依据（见 4.3）。
- **写入策略**：本期仅支持**新增**（按行生成新模板），不支持按编号/名称匹配更新已有模板；重复名称的处理见 4.5。

## 2. 导入流程图

### 2.1 导入主流程

```
下载导入模板(Excel)
        │  含表头、枚举字典、示例行、填写说明
        ▼
填写并上传 .xlsx
        │
        ▼
┌─────────────────┐
│ 1. 文件预检      │  格式/大小/表头一致性 → 不通过直接驳回
└────────┬────────┘
         ▼
┌─────────────────┐
│ 2. 解析 + 行级校验│  逐行：必填 / 枚举 / 类型能力矩阵 / 查重
└────────┬────────┘
         ▼
┌─────────────────┐
│ 3. 预览结果      │  成功 N 行 / 失败 N 行 / 错误明细可下载
└────────┬────────┘
   用户确认导入
         ▼
┌─────────────────┐
│ 4. 写入          │  按类型组装 config → 生成草稿/审核中模板
└────────┬────────┘
         ▼
┌─────────────────┐
│ 5. 结果反馈      │  成功数 + 跳转列表；失败可重试
└─────────────────┘
```

### 2.2 大文件异步流程

```
文件行数 > 阈值(如 500 行)
        │
        ▼
转为异步任务，立即返回"处理中"
        │
        ▼
后台解析 → 校验 → 写入（任务状态：处理中）
        │
        ▼
用户在"导入记录"页查看进度/结果（任务状态：完成/部分成功/失败）
        │
        ▼
完成后可下载结果报告
```

## 3. 模板下载逻辑

### 3.1 导入模板的内容

系统提供一个标准 Excel 模板，包含：

1. **填写说明 sheet**：每个字段的含义、是否必填、枚举可选值、与模板类型的匹配关系。
2. **数据填写 sheet**：表头 + 一到两行示例（示例行导入时需识别并跳过）。
3. **字典 sheet**（可选）：列出模板类型、能力开关等枚举的合法取值，供下拉/参考。

### 3.2 表头逻辑

表头分四组，按"模板主信息 → 时间能力 → 对象能力 → 条件能力 → 优惠能力 → 提交目标"顺序排列。能力开关列统一用"是/否"或"Y/N"表达布尔（在说明中约定一种）。

### 3.3 版本一致性

- 模板表头带**版本号**（或列签名）。
- 上传时校验文件版本与当前系统版本是否一致；不一致则提示"模板版本过旧，请重新下载"，避免字段缺失或错位。

## 4. 核心逻辑：解析与校验

校验分三层，**任一层失败均不影响其它层错误的收集**，最终在预览阶段一次性反馈全部错误。

### 4.1 第一层：文件预检（整体驳回型）

| 校验项 | 失败处理 |
|--------|----------|
| 文件格式必须为 .xlsx | 整体驳回 |
| 文件大小 ≤ 限定（如 10MB） | 整体驳回 |
| 表头与模板版本一致 | 整体驳回，提示重新下载 |
| 数据行数 > 0（不能只有表头/示例） | 整体驳回 |
| 单次行数 ≤ 上限（如 1000 行） | 整体驳回，提示拆分 |

### 4.2 第二层：行级基础校验（逐行标记错误，不中断）

每行独立校验，错误记到该行错误信息，不阻断其它行：

- **必填校验**：模板名称、模板类型必填。
- **枚举校验**：模板类型必须落在 {直降, 折扣, 满减满赠, 满赠券}；启用状态必须为 {启用, 禁用}；提交目标必须为 {草稿, 审核中}。
- **布尔列校验**：能力开关列取值必须为约定的布尔值表达（非法值视为"否"并给出警告，或视为错误——按系统约定统一）。
- **长度/格式校验**：模板名称长度、说明长度不超过主表限制。
- **类型与提交目标联动**：若提交目标为"审核中"，则名称/类型不可为空（与向导"提交审核"校验一致）。

### 4.3 第三层：业务校验（核心 —— 类型能力矩阵）

每一行的能力开关勾选，必须符合模板类型决定的能力可见性矩阵。**类型不支持的能力被勾选，视为错误行**（或按系统约定自动忽略并警告——本文档默认**报错**，避免静默丢失意图）。

能力开关 × 模板类型 可勾选矩阵（沿用促销模板 PRD 7.4）：

| 能力开关（Excel 列） | 直降 | 折扣 | 满减满赠 | 满赠券 |
|---------------------|:----:|:----:|:--------:|:------:|
| 商品范围 | ✅ | ✅ | ✅ | ✅ |
| 费用承担 | ✅ | ✅ | ✅ | ✅ |
| 商品可叠加 join | ✅ | ❌ | ❌ | ❌ |
| 整单限量 | ✅ | ✅ | ✅ | ✅ |
| 会员限量 | ✅ | ✅ | ✅ | ✅ |
| 门店限量 | ✅ | ✅ | ✅ | ✅ |
| 区域限量 | ✅ | ✅ | ✅ | ✅ |
| 满金额门槛 | ✅ | ✅ | ✅ | ✅ |
| 满数量门槛 | ✅ | ✅ | ✅ | ✅ |
| 阶梯 | ✅ | ✅ | ✅ | ✅ |
| 倍数 | ❌ | ✅ | ✅ | ✅ |
| 直降/折扣（优惠） | ✅ | ✅ | ❌ | ❌ |
| 满减/赠（优惠） | ❌ | ❌ | ✅ | ❌ |
| 上限设置 | ❌ | ❌ | ✅ | ❌ |
| 用券出券规则 | ❌ | ❌ | ❌ | ✅ |
| 赠券上限 | ❌ | ❌ | ❌ | ✅ |

附加的**互斥校验**（行内）：

- 满减满赠的"满减/赠优惠形式"若拆为多列（金额/比例/商品），则"商品"与"金额/比例"互斥，不可同时为"是"。
- 直降类型勾选"倍数" → 报错。

### 4.4 字典 / 关联转换逻辑

- 模板类型、启用状态等中文枚举，需在解析阶段映射为系统存储值（直降→`直降` 存储值等，沿用主表约定）。
- 导入数据**不含主外键 ID**（如门店、商品范围均不在本期导入范围），故无需做编码→ID 的关联解析。

### 4.5 重复数据逻辑

重复判定以**模板名称**为唯一识别依据（与向导"名称建议不重复"一致）：

| 场景 | 处理 |
|------|------|
| 文件内多行名称相同 | 仅首行视为有效，其余行标记"文件内重复"错误 |
| 名称与系统中已存在模板重复 | 该行标记"名称已存在"错误，不覆盖、不更新 |

> 本期不做"按名称匹配更新"策略；如后续需要，需单独增加"导入模式：新增 / 更新 / 新增或更新"开关。

## 5. 核心逻辑：数据写入

### 5.1 二维表 → config 结构组装

每行通过校验后，按模板类型组装为与向导一致的结构：

```
template 主表
 ├─ templateNo      ← 系统自动生成（不取 Excel 值）
 ├─ name            ← Excel 模板名称
 ├─ templateType    ← Excel 模板类型（映射后）
 ├─ status          ← 见 5.3 写入状态
 ├─ enableStatus    ← Excel 启用状态（默认启用）
 ├─ desc            ← Excel 模板说明
 ├─ creator/createAt← 当前登录人 / 系统时间
 └─ config
     ├─ basic（name/type/desc + time 能力开关）
     ├─ basic.object（商品/门店/用户/费用承担等能力开关）
     ├─ basic.other（退款/费用分摊/支付方式等开关）
     ├─ rule.promoType（与 templateType 对应）
     ├─ conditions（限量/门槛/阶梯/倍数能力开关）
     └─ rewards（直降折扣/满减赠/上限/用券出券/赠券上限开关）
```

组装规则：

- Excel 中未提供的能力开关列，按该类型的**默认值**回填（默认值与向导一致，如单品优惠默认勾选）。
- 该类型不支持的能力开关，强制置为关闭/缺省，**不写入 config**（即使 Excel 误填，因第三层校验已拦截）。
- 明细列表字段（阶梯档位、商品范围、时段范围等）写入**空数组 / 缺省结构**，留待向导补配。

### 5.2 编号生成

- templateNo 由服务端统一分配（沿用现有规则：当前最大编号 +1），**Excel 不提供、也不识别编号列**，避免并发冲突与越权指定。

### 5.3 写入状态（targetStatus）

按 Excel"提交目标"列决定：

| 提交目标 | 写入后 status | 备注 |
|----------|---------------|------|
| 草稿（默认） | 草稿 | 可后续在列表逐个提交审核 |
| 审核中 | 审核中 | 等同向导"生成并提交审核"，名称/类型必填校验已在第二层完成 |

> 不允许通过导入直接生成"有效/停用/作废"态；审核流转仍走列表的审核操作（含审核人 ≠ 提交人约束）。

### 5.4 事务粒度

- **行级独立提交**：每行作为一个独立写入单元，单行失败不影响其它行（部分成功）。
- 不做"全成功才提交"的全量事务（模板批量场景下，单行错误不应连累整批）。

## 6. 任务状态流转

导入任务（Import Task）状态机：

```
已上传 ──解析校验──▶ 校验通过(待确认) ──用户确认──▶ 写入中 ──▶ 完成
   │                    │                          │
   │ 解析失败            │ 用户取消                  │ 写入异常
   ▼                    ▼                          ▼
  解析失败            已取消                      失败(可重试)

若为部分成功：写入中 ──▶ 部分成功（成功 N / 失败 M）
```

| 状态 | 含义 |
|------|------|
| 已上传 | 文件已接收，待解析 |
| 校验通过(待确认) | 解析校验完成，等待用户在预览页确认 |
| 写入中 | 用户已确认，正在落库（异步任务可见） |
| 完成 | 全部行写入成功 |
| 部分成功 | 部分行成功、部分失败（附错误报告） |
| 失败 | 写入阶段整体异常，可重试 |
| 已取消 | 用户在校验通过后放弃导入 |

任务记录保留期限建议 ≥ 90 天，含操作人、文件名、时间、成功/失败计数。

## 7. 错误反馈与报告

### 7.1 预览阶段反馈

校验完成后，预览展示：

- 总行数、可导入行数、错误行数。
- 错误明细列表：行号 + 字段 + 错误原因（如"第 12 行 倍数：直降类型不支持倍数开关"）。

### 7.2 错误报告下载

- 提供"下载错误报告"，导出**仅含错误行**的 Excel，并在行尾追加"错误原因"列，便于用户修正后重新上传。
- 写入阶段的部分失败，同样生成结果报告（含成功行编号、失败行原因）。

### 7.3 错误信息要求

错误原因需**可定位、可操作**：指明行号、字段名、具体原因，避免"导入失败"这类无信息提示。

## 8. 异常流程

| 场景 | 处理 |
|------|------|
| 上传非 .xlsx / 文件损坏 | 文件预检驳回，提示"请使用标准模板的 xlsx 文件" |
| 模板版本与系统不一致 | 驳回，提示"模板版本过旧，请重新下载最新模板" |
| 表头被改动/列缺失 | 驳回，提示"表头与模板不符，请勿修改表头" |
| 数据行仅含示例行 | 提示"无可导入数据，请删除示例行后填写真实数据" |
| 单行必填缺失 | 该行标记错误，不阻断其它行 |
| 能力开关与类型不匹配 | 该行标记错误（默认报错策略） |
| 文件内名称重复 | 仅首行有效，其余标记"文件内重复" |
| 名称与系统重复 | 该行标记"名称已存在"，不覆盖 |
| 异步任务超时/服务异常 | 任务置"失败"，可从导入记录页重新发起 |
| 用户在"待确认"态关闭页面 | 任务保留为"待确认"，可在导入记录页继续确认或取消 |

## 9. 非功能与安全

- **性能**：同步导入建议 ≤ 500 行；> 500 行走异步队列。单任务上限 1000 行，超限提示拆分。
- **权限**：导入权限独立于"新建模板"权限，需单独授权（建议归入配置员/管理员角色，沿用促销模板 PRD 4.4 的角色模型）。无权限者不可见入口、不可下载模板、不可上传。
- **审计**：每次导入任务记录操作人、时间、文件名、成功/失败数；导入生成的每个模板，其 creator/createAt 取当前登录人，纳入现有模板审计链路。
- **数据隔离**：导入生成的模板，其数据权限（区域/组织可见性）遵循现有模板数据权限规则。
- **安全**：上传文件需做类型与大小校验，防止恶意文件；服务端解析需限制单元格数量与解析时长，防 DoS。

## 10. 关键逻辑小结（一图）

```
Excel 二维行
   │
   ├─ 文件预检（格式/大小/表头/版本）── 整体驳回
   ├─ 行级基础校验（必填/枚举/长度）── 标错误行
   ├─ 业务校验：类型能力矩阵 + 互斥 + 名称查重 ── 标错误行
   │
   ▼ 全部通过/部分通过 → 预览
   │
   ▼ 用户确认
   │
   ├─ 按类型组装 config（不支持的能力不写入，明细留空）
   ├─ 服务端生成 templateNo
   ├─ 写入状态：草稿（默认） / 审核中
   ├─ 行级独立提交 → 部分 success
   │
   ▼
   结果反馈 + 错误报告下载
```
