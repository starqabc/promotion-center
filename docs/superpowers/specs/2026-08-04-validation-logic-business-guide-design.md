# 通用校验逻辑 - 业务方案补充设计

## 背景

原有的"通用校验逻辑"文档主要面向开发团队，作为技术实现规范使用。为了让业务人员也能清晰理解校验逻辑和处理方案，需要在保留现有技术内容的基础上，补充面向业务人员的方案说明。

## 设计目标

1. 保持技术实现规范的完整性，开发团队仍可按原内容实现
2. 为业务人员提供通俗易懂的校验逻辑说明
3. 清晰分离业务方案和技术实现，各取所需
4. 提供完整的冲突处理指引和异常场景说明

## 文档结构设计

采用**双部分结构**：
- 前半部分：业务方案（面向业务人员）
- 后半部分：技术实现（面向开发人员，保留现有内容）

### 业务方案部分（新增）

#### 1. 业务背景与价值

**内容包括：**
- 为什么需要校验？（避免促销冲突、结算异常、顾客体验混乱）
- 校验的业务价值（保障促销活动数据一致性）
- 适用活动类型：组合价、一口价活动
- 核心原则：同一商品在同一时间段、同一门店只能参与一个促销活动

**表达方式：** 用业务语言描述，避免技术实现细节

#### 2. 校验规则说明（通俗版）

**内容包括：**
- **三维判定规则**：时间、门店、商品三个维度同时满足才算冲突
- **时间交叉判定**：
  - 部分交叉：A开始 ≤ B开始 ≤ A结束
  - 完全交叉：两个活动时间完全重叠
  - 完全覆盖：一个活动时间完全包含另一个
- **门店重叠判定**：
  - 全部门店 vs 任何门店 → 直接重叠
  - 具体门店 → 比对门店编码列表
  - 门店组 → 展开为具体门店后比对
- **商品重叠判定**：
  - 全场商品 vs 任何商品 → 直接重叠
  - 具体商品 → 比对商品编码
- **参与校验的单据状态**：草稿、待审核、待生效、生效中的单据都会参与校验

**表达方式：** 每个规则配 1-2 个简单案例说明

#### 3. 触发场景与时机

**内容包括：**
- **点击"下一步"**：选择商品后立即校验，最早暴露问题
- **点击"保存"/"保存草稿"**：强校验，不允许保存冲突商品
- **点击"提交"/"提交审核"**：最终校验，防止草稿保存后产生新冲突
- **直接点击"提交"**：跳过步骤流程时的校验
- **导入活动/导入商品**：批量导入时的校验，采用"全有或全无"策略

**表达方式：** 每个触发场景说明"为什么会触发"和"触发后的表现"

#### 4. 冲突处理流程

**冲突提示内容：**
- **门店信息**：门店编码、门店名称
- **商品信息**：商品编码、商品名称
- 冲突单据编号（可点击跳转）
- 冲突单据状态
- 冲突活动时间
- 冲突活动方式
- 处理建议

**处理选项一：删除本单重复商品**
- 操作说明：从当前单据商品范围中移除交叉商品
- 适用场景：交叉商品非必须参与本次活动
- 附加功能：导出错误数据（Excel格式）

**处理选项二：终止前单交叉商品**
- 操作说明：系统自动创建促销终止单，终止前单中的交叉商品
- 适用场景：当前单据必须包含这些商品
- 操作步骤：点击按钮 → 系统创建终止单草稿 → 用户确认提交 → 终止单生效 → 重新校验

**表达方式：** 分步骤说明 + 决策树（什么情况选哪个方案）

#### 5. 异常场景说明

**内容包括：**
- **自身排除**：编辑模式下，当前单据自身不参与冲突校验

- **批量创建活动**：
  - 导入整个活动文件，逐条校验
  - 查到有重叠商品 → **全量导入失败（全量回滚）**
  - 导入是异步处理，页面给导入失败错误提示
  - 用户需要在活动列表页点击"导入导出记录"按钮查看冲突详情

- **导入商品范围**：
  - 创建活动时通过导入方式添加商品
  - 同步导入，解析阶段即执行校验
  - **正确商品正常导入，交叉商品进行页面提示**

- **编辑已有单据**：
  - 修改**时间、门店、商品**都会触发校验（和新增一样）
  - 修改后按新增逻辑执行校验

- **复制单据**：
  - 复制为新单据，**用户修改后再触发校验**（不立即触发）
  - 如果原单据活动时间已过去，用户调整时间后再校验

- **终止单已覆盖**：
  - 终止单状态为"**终止**"且终止时间 ≤ 当前单据开始时间
  - 该商品排除出冲突校验

- **终止单未生效**：
  - 终止单状态为"**草稿/审核中/待终止**"
  - 商品仍参与冲突校验

- **部分终止**：同一单据仅部分商品被终止，未被终止的商品仍需校验

**表达方式：** 每个场景用通俗语言解释 + 简单案例

#### 6. 常见问题 FAQ

**内容包括：**
- Q1：为什么"下一步"就要校验，而不是提交时才校验？
- Q2：为什么保存草稿时也要强校验？
- Q3：终止单创建了，为什么还提示冲突？
- Q4：如何查看已终止的商品？
- Q5：导入活动失败后，如何知道具体哪些商品冲突？
- Q6：选择"终止前单交叉商品"后，终止单多久生效？
- Q7：全部门店和具体门店如何判定重叠？

**表达方式：** 问答形式，每个问题给出简明解答
